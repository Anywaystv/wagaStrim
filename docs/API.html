API setup

Create cameras from another app and get their publishing and preview links. All examples use the default ports. Replace addresses and placeholders with your own.

1. Create the control token

On the server or computer running WagaStrim, open Setup. Under Reachability, click Generate control token, copy it to a password manager, then restart WagaStrim. This creates a random 256-bit secret and saves it as controlToken in config.json. The file path appears in the startup log. An existing token is never overwritten.

For a headless installation, run this on that machine, then restart WagaStrim:

curl -X POST http://127.0.0.1:7330/api/control/token

Windows PowerShell: use curl.exe in these examples. The response is {"token":"YOUR_SECRET","restartRequired":true} (201). A second request returns 409. This setup endpoint is local only; it is not on the public control API.

The token grants administration of all cameras. It is separate from camera keys: never put it into Moblin, OBS or a public webpage. Existing tokens can be read from config.json. To rotate one, stop WagaStrim, replace controlToken with a password-manager-generated secret of at least 32 characters, then restart and update your clients. Remove the field to disable the API.

2. Set the addresses

Stop WagaStrim before editing config.json. Merge these fields into the existing object; preserve the other settings and ingests:

{
  "publicHost": "192.168.1.50",
  "controlLan": true,
  "controlRemote": false
}

Use your server's Wi-Fi/VPN IP or public hostname for publicHost. Restart after editing. Returned media links use this host, or 127.0.0.1 if unset (only usable on the server itself). HTTPS links use publicUrl when configured. The API never guesses a public address from the request.

Control requests go to TCP 7333 and require Authorization: Bearer YOUR_SECRET. Setup remains local on TCP 7330. The Local/Remote access toggles control allowed API clients, not camera access. They do not open firewall or router ports. For a remote server's setup page, use an SSH tunnel to its loopback port 7330.

HTTP exposes keys and tokens. Use HTTPS or an encrypted VPN outside a trusted local connection. For built-in HTTPS, set tlsCert and tlsKey to trusted certificate files and set publicHost to the certificate's hostname, then restart. Both signaling and control use HTTPS on their existing ports. A signaling publicUrl alone does not secure TCP 7333; secure the control listener separately if using a reverse proxy. Restrict proxy access too: access toggles inspect the direct peer, not forwarded headers.

3. Generate camera keys and links

Send a name (1–48 characters). Keep your token out of shared shell history and logs.

curl http://127.0.0.1:7333/control/ingests -H "Authorization: Bearer YOUR_SECRET" -H "Content-Type: application/json" -d '{"label":"Phone"}'

Windows PowerShell can pass the JSON without shell-quoting differences:

$credential = Read-Host "Control token"
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:7333/control/ingests -Headers @{Authorization="Bearer $credential"} -ContentType application/json -Body '{"label":"Phone"}'

A 201 response contains the camera's settings and links. Keys below are abbreviated:

{
  "id": "...",
  "label": "Phone",
  "senderKey": "s_...",
  "receiverKey": "r_...",
  "codecs": ["h264"],
  "delayMs": 2000,
  "links": {
    "moblin": "whip://192.168.1.50:7331/whip/s_...",
    "whip": "http://192.168.1.50:7331/whip/s_...",
    "whep": "http://192.168.1.50:7331/whep/r_...",
    "player": "http://192.168.1.50:7331/player/r_..."
  }
}
links.moblin
Paste into Moblin. HTTPS uses whips://.
links.whip
Publishing URL for other WHIP clients. The sender key is already in the URL.
links.player
Preview in a browser or an OBS Browser Source. Use H.264 and Opus for the simplest setup. Enable Control audio via OBS; disable Shutdown source when not visible.
links.whep
Raw WHEP endpoint for compatible receivers; not a browser page.

Sender keys allow publishing; receiver keys allow viewing. Treat both as secrets. New cameras default to H.264 and 2000 ms delay; edit them in Setup. Audio follows the sender, but AAC needs a compatible receiver and will not play in the built-in browser preview. WagaStrim does not transcode or push to Twitch/Kick; receive the feed in OBS and stream from OBS to your provider.

Allow TCP 7331 for signaling and UDP 7332 for media. Cellular connections need reachable public addresses and any necessary router forwarding. An API success does not prove media reachability.

4. Retrieve cameras and status

curl http://127.0.0.1:7333/control/ingests -H "Authorization: Bearer YOUR_SECRET"
curl http://127.0.0.1:7333/control/stats -H "Authorization: Bearer YOUR_SECRET"

The first returns {"ingests":[...]}, including keys and links for every camera (empty array when none exist). Stats returns an object keyed by camera ID, without secrets. Check live to see whether a publisher is active. Repeated create requests make different cameras; after a lost response, list cameras before retrying. Names are not unique identifiers.

Deployment-owned camera lists

PUT /control/ingests accepts {"ingests":[...]} and replaces the entire list. This is for a dashboard that owns its camera database. Keep every camera you want to retain. An empty list deletes all cameras.

Each camera has id (nonempty and unique), label, senderKey (s_ + 32 lowercase hex characters), receiverKey (r_ + 32 lowercase hex characters), codecs (h264, h265, av1), delayMs (0–10000) and optional syncGroup. Keys must be unique and cryptographically random. Strip the read-only links field from GET results before PUT. Missing cameras and changed keys/codecs disconnect existing sessions; 204 means saved. There is no merge or conflict detection: use one list owner. For manual deletion, use Remove in Setup.

Errors

400: invalid JSON, unknown fields or invalid camera settings. 404: missing/wrong token, blocked client address or unknown route. 409: local token already exists. 429/503: request limits; back off before retrying. 500: camera/token could not be saved; check the server log. Connection refused usually means WagaStrim needs a restart after token creation, the API is disabled, or the listener/firewall address is wrong.
